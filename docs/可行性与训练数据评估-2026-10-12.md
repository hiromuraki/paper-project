# 轻量方案：可行性、数据来源与骨骼合成

> 历史记录：文中引用的旧生成、体检及打包脚本已在 scripts 整理时移除，相关旧命令不适用于当前目录。当前工具与使用方法以项目 README 为准。

评估日期：2026-10-12。以本地代码、实际数据清点、小规模运行和下列一手资料为依据。未改动现有模型、训练逻辑或原有数据。

## 结论

单动作、已切好完整动作片段、限定机位和错误类型的二分类 demo 可行。当前实现是管线原型，尚未证明真实人体动作质量判别能力。主要瓶颈是标签定义和真实数据覆盖，不是缺少更大的模型。

可以完全绕过视频生成骨骼训练数据。推荐路线是「少量真实骨骼作为锚点 + 有约束的运动编辑/合成 + 真人独立测试集」。纯合成能验证规则与代码，但不能独自证明部署到真实姿态估计输入时有效。

### 优先处理的问题

1. **现有合成数据没有动作语义。** `make_synthetic_data.py` 每个关节主要沿同一直线做波形运动；正负样本相位、幅度、噪声存在系统性区别。`make_mock_dataset.py` 同样是波形，并独立生成 2D/3D，错误类型字段没有对应的动作编辑。高分只能说明这些分布可分。前一个脚本也没有把所有随机操作绑定到传入 generator，seed 不能完全复现坐标。
2. **混合缺失模态存在真实 bug。** `pack_dataset.collect_split` 只追加存在的模态，导致 x2d/x3d 列表长度与 y 不一致；Dataset 不读取保存的 has2d/has3d。用本地三条混合样例复现：y 长度 3、两个模态长度均为 2；前两条被当成双模态，第三条 IndexError。全数据只有 2D、全数据只有 3D、全数据都有两者是另一回事。正式扩数据前应采用每样本占位、显式 mask 和严格长度校验。
3. **绝对速度被预处理削弱。** 所有片段重采样到固定帧数，fps/原始时长不参与模型，差分也不是每秒速度。同一路径整体快慢不同可能变成几乎相同的输入。要判断“过快”，需保留 duration、时间戳或物理时间速度；只看相对下降/上升节奏则仍有部分信息。
4. **动作定义与特征应匹配。** 每帧根对齐丢失全局髋运动，无法直接使用世界坐标下降量；仍可通过相对角度判断幅度。当前尺度采用平均关节到根距离，会随动作姿态分布变化；可以对比用固定骨段长度归一化的基线。
5. **模型结构应如实描述。** 没有显式时间位置编码；差分提供部分动态信息，但对顺序/阶段的建模需做验证。num_layers 是反复调用同一个空间层和时间层，即共享权重；门控是每样本一个标量。缺一个模态时仍计算两个编码器，不能把参数少直接等同于低延迟。
6. **评估还不完整。** evaluate 默认读配置里的 val，没有独立 test 参数；可另写配置指定测试文件。当前 F1/recall 是以 good=1 为正类，不能当成“错误召回率”，后者应额外报告 TN/(TN+FP)。没有按错误类型、受试者、视角汇总，也没有校准与拒判机制。

以上是检查结论，本次未直接重构这些模块。

## 哪些内容能从骨骼判断

先把任务固定为某一种深蹲规范，而非所有深蹲的统一正确性。相同前倾角在不同深蹲类型、体型、负重和目标下含义不同，程序阈值不是通用运动标准。

- 较适合：动作幅度、明显左右不对称、较大的躯干角度偏差、完整动作起止状态。
- 依赖视角：侧面适合深度/前倾，正面适合左右差异；单个 2D 视角不能保证看到全部错误。需要按可见性限制任务，而非给不可见错误强行贴负标签。
- 当前 H36M17 信息不足：足跟离地与脚尖朝向（无独立足跟/脚趾）、细微腰椎弯曲、受力/负重、疼痛等。3D 若由单目估计得到，也不是天然准确的真值。
- 观测噪声不等于动作错误：正常骨骼加抖动后一般仍应是正常动作，另记观测质量。严重缺失应拒判或补采，不能直接等同于 False。

## 需要多少数据

这里的数量是工程预算建议，不是保证精度的统计定律。单位是一条完整独立动作重复，不是帧数、重叠窗口或投影视角数。

| 阶段            | 真人/真实捕获骨骼预算               | 合成数据预算   | 目标                                           |
| --------------- | ----------------------------------- | -------------- | ---------------------------------------------- |
| 流程验证        | 可暂为 0                            | 100–500        | 验证格式、训练、推理与可视化；不报告真实准确率 |
| 单动作受限 demo | 10–20 人，约 300–1,000 次重复       | 2,000–10,000   | 限定机位与 2–4 类可观测错误，验证真实迁移      |
| 更稳健原型      | 30–50 人以上，约 1,500–5,000 次重复 | 按学习曲线追加 | 增加体型、设备、机位、动作风格；仍需独立测试   |

一个具体起步预算：20 人 ×（15 次正常 + 3 类错误各 5 次）=600 次重复。先按人划为 12/4/4 人，即 360/120/120 条 train/val/test，再只扩增训练集。此时测试集每错误只有 20 条，1 条误差就影响 5 个百分点，只能作初步判断；要稳定分析错误类型，争取独立测试中每类有 50–100 条且跨多人。

标注时保留 error_type、severity、标注者、置信度；边界样本先标 uncertain，不强行二值化。同一原动作的裁剪、编辑、镜像、多视角投影必须在同一划分；subject_id 相同亦应同组。帧数或合成数量不能替代真人数量。

以 100/300/600/1000 条真实训练数据做学习曲线；固定真实验证/测试人员，比较真实-only、合成-only、真实+合成，以及角度规则/DTW 基线。如果合成只提高合成测试分数，不继续靠堆数量解决。

## 合成路线

最推荐编辑真实 3D 动作的关节旋转曲线：保留体型与原始节奏，控制膝/髋角、躯干方向、左右相位等，再通过正向运动学生成关节位置；涉及脚接触时加逆运动学约束。缺真实种子时，可先用程序化骨架与轨迹验证。

完整流程：定义动作及标签规则 → 生成人体骨段与关节轨迹 → 约束骨长/角度/脚接触 → 对特定阶段施加语义错误 → 用相机投影得到同步 2D → 独立于标签加入观测噪声 → 人工审核与质检 → 按源动作/人分组。

可控编辑包括幅度不足、左右不同步、规定任务下的前倾偏差、起止未伸直。膝内扣需要同时维护腿长与脚接触；节奏错误需要保留原时长。不要用随机乱扭关节作为主要负样本，也不要用“生成失败”自动赋错误标签。

正负样本要共享相同的设备、体型、视角、噪声机制和来源比例，否则模型可能只识别生成器或设备。几千条训练样本可先做每批约一半真实、一半合成的实验起点，再由真实验证结果选择比例；最终阶段可用真实数据微调。

## 本次实际生成的样例

脚本：`scripts/make_kinematic_squat.py`。

数据：`runs/kinematic_squat_v1/raw/`，共 120 条，60 条规则内正常、30 条幅度不足、30 条躯干前倾偏大；10 个虚拟体型，每个 3 组源动作，每组 4 个变体。按虚拟体型拆分 72/24/24 条，各划分正负均衡。虚拟体型不是 10 名真实受试者。

每条包含 kp2d.npz、kp3d.npz、meta.json。采用米单位、Y 向上、Z 向前；2D 是归一化图像坐标、Y 向下。2D 来自对应 3D 的透视投影。记录 synthetic、label_source、source_motion_id、seed 和生成参数。当前 pack_dataset 不保留全部这些字段，因此 raw/meta.json 必须保留；正式版打包应增加来源字段。

脚本用双连杆腿部逆运动学保持脚踝位置与骨长，躯干是刚性链。验证了数值有限、3D 骨长恒定、脚踝不离地；最大浮点骨长漂移约 2.31e-7 米。**这些检查不等于动力学、平衡、碰撞或专家质量审核。** 当前未加入膝内扣、腰椎形变、脚趾/足跟、追踪噪声及复杂人体风格。

已打包至 `runs/kinematic_squat_v1/packed/`，并用独立配置完成 2 epoch smoke 训练。第一轮 val accuracy=0.5833、good F1=0.2857、AUROC=0.8194；第二轮 val accuracy=0.5、good F1=0、AUROC=1。这也说明排序指标高并不代表 0.5 阈值分类可用。不能将这次短训练用作模型方案优劣结论。

生成器已有骨长、数值和脚接触断言；额外管线检查记录在 `runs/kinematic_squat_v1/pipeline_validation.json`。现有查看器可导入单条 kp3d.npz，无需视频。

复现（输出目录必须尚不存在，防止覆盖）：

```powershell
.\.venv\Scripts\python.exe scripts/make_kinematic_squat.py --out runs/kinematic_squat_v2/raw --seed 20261012
.\.venv\Scripts\python.exe scripts/pack_dataset.py --dataset runs/kinematic_squat_v2/raw --out runs/kinematic_squat_v2/packed --action squat
```

建议下一步按顺序：修复混合模态与数据校验 → 固定深蹲判定规范和支持视角 → 接入一批真实骨骼 → 在真实验证集比较规则/DTW与当前网络 → 对真实种子做受约束的错误编辑 → 扩数据与实时分段。先取得真人测试结果，再决定是否扩大模型。
