# 模型模块说明

本文档说明当前轻量二分类模型的四个关键位置：

1. 单模态编码器；
2. 2D/3D 融合；
3. 输出头；
4. 时序建模。

每个位置都回答三个问题：

- 它在做什么？
- 当前代码怎么实现？
- 什么时候替换，替换后有什么代价？

---

## 0. 整体流程

```text
2D 骨骼 ──→ 2D 单模态编码器 ──┐
                              ├─→ 2D/3D 融合 ─→ 输出头 ─→ True / False
3D 骨骼 ──→ 3D 单模态编码器 ──┘
```

时序建模不是独立模块，而是嵌在单模态编码器内部：

```text
单模态编码器 = 输入投影 + 关节空间注意力 + 时间注意力 + 池化
```

对应代码：

- `skeleton_demo/src/skeleton_demo/model.py`
- 关键类：`SkeletonEncoder`、`BinarySkeletonModel`

---

## 1. 单模态编码器

### 作用

把一条骨骼序列压缩成一个动作表示。

输入：

- 2D：`[B, T, 17, 6]`
- 3D：`[B, T, 17, 9]`

输出：

- `[B, T, 17, d]` 的隐藏特征，再池化成 `[B, 2d]`。

### 当前实现

`SkeletonEncoder` 使用 factorized spatio-temporal Transformer：

1. `Linear` 投影到 `d` 维；
2. 加关节嵌入；
3. Spatial Transformer：在同一帧的 17 个关节之间做注意力；
4. Temporal Transformer：在同一个关节的 T 帧之间做注意力；
5. 重复 `num_layers` 次；
6. `LayerNorm`；
7. mean + max 池化。

### 为什么这样设计

- 关节数只有 17，帧内注意力便宜；
- 2D 和 3D 可以共享结构、独立参数；
- 实现简单，方便先跑通数据；
- 时间与空间注意力分开，便于后续替换其中一部分。

### 可替换为

| 方案 | 优点 | 代价 |
|---|---|---|
| ST-GCN | 骨架图先验强、参数少、经典稳定 | 需要邻接矩阵，灵活性一般 |
| CTR-GCN | 精度强，适合骨骼识别 | 结构更复杂，代码改动较大 |
| PoseC3D | 骨骼热图体，鲁棒性好 | 丢失精确坐标，显存更大 |
| MotionBERT | 预训练运动表征，迁移能力强 | 依赖权重，模型更重 |

### 选择建议

- demo：当前 Transformer 或 ST-GCN；
- 追求精度：CTR-GCN 或 MotionBERT；
- 骨骼噪声大：PoseC3D；
- 参考骨骼/单样本：MotionBERT 或预训练表征。

## 2. 2D/3D 融合

### 作用

决定 2D 和 3D 信息如何合成一个动作表示。

输入：

- \(p^{2D} \in \mathbb{R}^{2d}\)
- \(p^{3D} \in \mathbb{R}^{2d}\)

输出：

- \(h \in \mathbb{R}^{2d}\)

### 当前实现

门控融合：

$$
\alpha = \sigma\left(\operatorname{MLP}([p^{2D}, p^{3D}])\right)
$$

$$
h = \alpha \odot p^{2D} + (1-\alpha) \odot p^{3D}
$$

缺失模态：

- 只有 2D：\(\alpha = 1\)；
- 只有 3D：\(\alpha = 0\)；
- 两者都有：\(\alpha\) 由网络学习。

### 为什么这样设计

- 实现简单；
- 参数量小；
- 天然支持模态 dropout；
- 便于先验证“2D+3D 是否比单模态更好”。

### 可替换为

| 方案 | 优点 | 代价 |
|---|---|---|
| 早融合 | 最简单，直接拼接 | 坐标尺度和模态差异难处理 |
| Cross-attention | 能在关节和时间层面对齐 2D/3D | 参数量大，需要更多数据 |
| 可靠性门控 | 显式建模 2D/3D 置信度 | 需要定义噪声模型或不确定性头 |
| Token-level MoE | 细粒度选择模态 | 实现复杂，训练不稳定 |

### 选择建议

- demo：当前门控融合；
- 2D 高可信、3D 次可信：可靠性门控；
- 两者都可信且数据充足：cross-attention；
- 现场可能缺模态：当前门控 + modality dropout 就够用。

## 3. 输出头

### 作用

把融合后的特征映射成最终判断。

当前输出：

$$
\text{logit} \in \mathbb{R}
$$

推理时：

$$
\text{prob} = \sigma(\text{logit})
$$

$$
\text{decision} =
\begin{cases}
\text{True}, & \text{prob} \ge 0.5 \\
\text{False}, & \text{prob} < 0.5
\end{cases}
$$

### 当前实现

```text
Linear(2d → d)
→ GELU
→ Dropout
→ Linear(d → 1)
```

训练损失：

$$
\mathcal{L}
=
\operatorname{BCEWithLogitsLoss}(\text{logit}, y)
$$

### 可替换为

| 方案 | 作用 | 代价 |
|---|---|---|
| 温度缩放/保序回归 | 概率校准 | 需要额外验证集 |
| 分布式输出头 | 输出均值和方差，估计不确定性 | 损失函数更复杂 |
| 多标签输出头 | 同时输出错误类型 | 需要错误类型标签 |
| one-class 输出头 | 只用正样本训练，异常即 False | 对负样本分布敏感 |
| 原型/度量输出头 | 和参考骨骼比较 | 需要参考模板或配对数据 |

### 选择建议

- demo：当前二分类头；
- 输出概率要可信：加温度缩放；
- 需要“不确定时不判”：分布式或 evidential head；
- 负样本很少：one-class；
- 后续引入参考骨骼：原型/度量头。

## 4. 时序建模

### 作用

建模动作随时间的演化，包括顺序、速度、节奏和相位。

当前时序建模位于：

- `SkeletonEncoder.temporal`

### 当前实现

对每个关节，沿 T 帧做 self-attention：

```text
[B*17, T, d] → Temporal Transformer → [B*17, T, d]
```

然后恢复为 `[B, T, 17, d]`。

### 当前限制

- 默认是双向全序列注意力，不是因果的；
- 实时推理需要改成 causal mask 或滑动窗口；
- 复杂度随 T 增长；
- 小数据上可能过拟合。

### 可替换为

| 方案 | 优点 | 代价 |
|---|---|---|
| TCN | 因果、快、适合在线 | 感受野有限 |
| GRU/LSTM | 天然流式，简单 | 顺序训练慢，长程能力弱 |
| Mamba/SSM | 线性复杂度，适合长序列 | 生态和调参成本较高 |
| causal Transformer | 兼容在线推理 | 需要 mask，训练目标要调整 |
| 固定窗口 Transformer | 实现简单 | 长动作会丢上下文 |

### 选择建议

- 离线 demo：当前 Temporal Transformer；
- 实时滑动窗口：TCN 或 causal Transformer；
- 长序列：Mamba 或 TCN；
- 小数据：TCN/GRU + 强正则。

---

## 5. 当前 demo 的推荐组合

先不要全部替换，按收益排序：

1. 保持当前门控融合和输出头；
2. 如果精度不够，把单模态编码器换成 CTR-GCN 或 MotionBERT；
3. 如果要做实时，把时序建模换成 causal Transformer 或 TCN；
4. 如果要做参考动作对比，把输出头换成原型/度量头；
5. 如果要做概率校准，加温度缩放或分布式输出头。
