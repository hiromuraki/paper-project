## 1. 问题定义

### 1.1 输入

单个动作的骨骼序列。

```text
2D: [T, 17, 2]
3D: [T, 17, 3]
或者同时输入 2D 和 3D
```

当前阶段只判断一个动作，例如深蹲、卧推、硬拉或弓步。后续再增加 `action_id` 维度。

### 1.2 输出

```text
logit     实数
prob      [0, 1]
decision  True / False
```

`True` 表示动作良好，`False` 表示动作错误或扭曲。

当前只需要二值判断，不需要输出具体错误类型。

---

## 2. 数据方案

### 2.1 正样本 True

- 标准动作视频提取的骨骼；
- 自己录制的规范动作；
- 同一动作的不同正常风格；
- 不同受试者、不同视角的正常动作。

### 2.2 负样本 False

优先构造可重复的错误类型：

| 错误类型      | 例子                   |
| ------------- | ---------------------- |
| 幅度不足      | 深蹲下蹲不够深         |
| 幅度过大      | 过度前倾、过度伸展     |
| 姿态错误      | 膝内扣、塌腰、耸肩     |
| 左右不对称    | 左右膝角差异过大       |
| 节奏错误      | 下降或上升过快、无停顿 |
| 起始/结束错误 | 未站直、未锁定         |
| 其他动作      | 用其他动作作为难负样本 |

即使最终只输出 True/False，也建议在数据元信息里保留错误类型，方便分析模型到底学到了什么。

### 2.3 划分

最低要求：

- 按 clip 划分，不能按帧划分；
- 同一个 clip 不能同时出现在训练和测试中；
- 保留一个 held-out 测试集。

推荐：

- 按受试者划分；
- 如果视角多，按视角留出一部分测试。

## 3. 模型结构

### 3.1 最小版本

适合最快跑通：

- 输入归一化：根节点对齐、尺度归一化；
- 特征：坐标 + 骨向量 + 速度；
- 编码器：ST-GCN、CTR-GCN 或小型时序 Transformer；
- 2D/3D 同时输入时：各自投影后拼接，或使用简单 gated fusion；
- 时序池化：mean + max；
- 分类头：MLP → 1 个 logit → sigmoid。

### 3.2 推荐 demo 版本

当前代码里的模型不是直接调用现成动作识别模型，而是用 PyTorch 标准模块组装的任务专用轻量模型。

使用的标准组件：

- `nn.Linear`
- `nn.TransformerEncoderLayer`
- `nn.LayerNorm`
- `nn.MLP` 风格的分类头

任务专用设计：

- H36M 17 关节的 2D/3D 双分支；
- 每帧内做关节空间注意力；
- 跨帧做时间注意力；
- mean + max 双池化；
- 可学习的 2D/3D 门控融合；
- 支持缺失一个模态；
- 二分类输出 `True / False`。

架构图：[轻量模型架构.svg](轻量模型架构.svg)

![轻量模型架构](轻量模型架构.svg)

更详细的模块职责说明见：[模型模块说明.md](模型模块说明.md)

```text
2D 输入: [B, T, 17, 2]
3D 输入: [B, T, 17, 3]
        ↓
根节点对齐 + 尺度归一化 + 时间重采样
        ↓
特征构造：坐标 + 骨向量 + 速度
        ↓
2D: [B, T, 17, 6]     3D: [B, T, 17, 9]
        ↓                       ↓
Linear(6→d) + 关节嵌入     Linear(9→d) + 关节嵌入
        ↓                       ↓
关节空间 Transformer       关节空间 Transformer
        ↓                       ↓
时间 Transformer           时间 Transformer
        ↓                       ↓
mean + max 池化            mean + max 池化
        ↓                       ↓
       p_2D                    p_3D
        └──────────┬───────────┘
                   ↓
          门控融合：α = σ(MLP([p_2D, p_3D]))
          h = α ⊙ p_2D + (1-α) ⊙ p_3D
                   ↓
          MLP → 1 个 logit → sigmoid
                   ↓
           threshold → True / False
```

模态门控：

$$
\alpha = \sigma\left(f_{\text{rel}}(h_{2D}, h_{3D})\right)
$$

$$
h = \alpha \odot h_{2D} + (1-\alpha) \odot h_{3D}
$$

如果只有 2D 或只有 3D，直接走对应分支，不使用门控。

### 3.3 模型规模建议

| 参数       | 建议     |
| ---------- | -------- |
| 帧数 T     | 64 或 96 |
| 关节数     | 17，H36M |
| 隐藏维度 d | 128      |
| 注意力头数 | 4        |
| 编码层数   | 2–3      |
| dropout    | 0.1–0.3  |
| 分类头     | 2 层 MLP |

## 4. 训练

### 4.1 损失

$$
\mathcal{L}
=
\operatorname{BCEWithLogitsLoss}(z, y)
$$

类别不平衡时使用 `pos_weight`。

### 4.2 数据增强

骨骼序列必须做增强，否则模型容易记住受试者风格和机位：

- 时间重采样：加快或减慢；
- 时间裁剪：随机截取动作窗口；
- 镜像：左右翻转；
- 关节噪声：小幅度高斯扰动；
- 尺度扰动；
- 3D 旋转扰动；
- 关节 dropout；
- 模态 dropout：随机丢 2D 或 3D。

### 4.3 训练配置建议

| 项           | 建议              |
| ------------ | ----------------- |
| optimizer    | AdamW             |
| lr           | 1e-3 到 1e-4      |
| weight decay | 1e-4              |
| batch size   | 32 或 64          |
| epochs       | 50–100            |
| 调度         | cosine 或 plateau |
| 早停         | 验证集 F1 或 loss |

### 4.4 过拟合问题

骨骼序列比原始视频更轻，但不等于不会过拟合。它仍然可能学到：

- 受试者体型和运动风格；
- 相机视角产生的 2D 投影差异；
- 动作节奏和个人习惯；
- 拍摄设备与骨骼提取模型的系统偏差。

demo 阶段可以接受同一环境内的过拟合；如果要稍微稳一点：

- 按受试者划分训练/验证；
- 做时间与镜像增强；
- 训练时随机丢模态；
- 保留一个独立测试集。

## 6. 实时推理

外部姿态模型持续输出骨骼帧，模型使用滑动窗口判断：

```text
骨骼流
  → 环形缓冲区（T 帧）
  → 归一化
  → 模型
  → prob
  → 平滑（EMA / 中值滤波）
  → 阈值
  → True / False
```

建议：

- 窗口 T 取 48–96 帧；
- 每 1–5 帧推理一次，不必逐帧；
- 用滑动平均或中值滤波防止输出抖动；
- 加一个简单滞回阈值，例如：
  - prob > 0.65 判 True；
  - prob < 0.35 判 False；
  - 中间保持上一次状态。

### 每个 clip 的文件

`kp2d.npz`：

```text
keypoints: [T, 17, 2] float32
fps:       scalar，可选
```

`kp3d.npz`：

```text
keypoints: [T, 17, 3] float32
fps:       scalar，可选
```

关节顺序固定为 H36M 17。

`meta.json` 推荐字段：

```json
{
  "clip_id": "clip_good_0001",
  "action_id": "squat",
  "label": 1,
  "label_name": "good",
  "subject_id": "s01",
  "view": "front",
  "fps": 30,
  "num_frames": 96,
  "error_type": null,
  "severity": 0,
  "start_frame": 0,
  "end_frame": 95,
  "has_2d": true,
  "has_3d": true,
  "joint_format": "h36m_17"
}
```

`remark.txt` 只用于人工记录，不参与训练。

### 数据要求

- 一个 clip 只放一次完整动作；
- 2D 和 3D 必须同帧、同关节顺序、同时间轴；
- 至少提供 2D 或 3D 中的一个；
- 同一个 clip 不能同时出现在 train 和 test；
- 尽量按 subject 或 view 划分；
- 不要只收集一种错误类型；
- mock 数据只是格式样例，不是真实训练数据。
