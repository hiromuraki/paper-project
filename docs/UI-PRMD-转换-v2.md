# UI-PRMD 转换 v2

运行（项目根目录）：

```powershell
# 不带参数或 --help：只显示帮助，不执行转换
uv run scripts/convert_ui_prmd.py --help
# 全部动作，使用分片，正面投影，允许插值 10 帧以内的内部缺口
uv run scripts/convert_ui_prmd.py --root dataset-raw/UI-PRMD --out dataset-ui-prmd-new --movement all --segmented --view front --max-gap 10 --fps 30
```

脚本没有默认转换参数。必须显式指定 `--root`、`--out`、`--movement`、`--view`、`--max-gap`、`--fps`，以及 `--segmented` / `--whole-trial` 中的一个。只转换深蹲可用 `--movement m01`；`--view side` 使用侧面投影；`--max-gap 0` 禁止插值。不要同时加入分片与整体 trial，避免重复样本。

输出目录必须为空。已有 `dataset-ui-prmd` 是先前的转换结果；再次运行请指定新的空目录。目录冲突会给出简短提示并退出，不打印堆栈，不修改已有数据。

输出结构为 `dataset-ui-prmd/{train,val,test}/包名/{kp3d.npz,kp2d.npz,meta.json,remark.txt}`。受试者 s01–s06 为 train，s07–s08 为 val，s09–s10 为 test；动作与标签来源记录在 meta 中。多个动作共同输出时，训练应按 meta.action_id 过滤，不要将全部动作打包并标成 squat。

旧转换的问题是：Vicon Z 轴向上，但 2D 投影使用了 X、Y 平面，使得身高方向被丢掉；3D 又保留了 Z-up，与项目的 Y-up 增广不一致。v2 用每段的水平髋部基线确定人体左右方向，固定 lab Z 为竖直方向，用叉积构造第三轴，整段只做一次行列式 +1 的刚体旋转。毫米转米，以首帧盆骨为坐标原点，保留后续整体位移，不逐帧拉直身体，也不改变骨段长度。

3D 为 `[T,17,3]` float32、Y-up，输出帧率由必填的 `--fps` 指定，原始 Vicon 为 100 FPS。H36M-17 的映射来源写在 conversion_report.json 中；髋 / 膝 / 肩等依然是体表标记近似关节位置，不能当成经过人体解剖标定的关节中心。Kinect 的尺度 / 相对坐标问题尚未解决，转换器不混入 Kinect。

2D 为同一份 3D 的正面或侧面正交投影，使用相同帧数、FPS、关节顺序。取左右与竖直轴，保持横纵同尺度，图像 Y 向下，整段归一化至 0.05–0.95 范围。`derived_2d=true` 明确说明它是合成投影，并非真实相机观测，不可用于真实 2D 精度结论。

缺失处理：全零或非有限值标记为缺失；仅插值被有效帧包围、不超过 10 帧的内部短缺口（`--max-gap` 可调整）。不外推首尾，也不凭空重建整段缺失的必需关节。头 / 腕等多个标记的平均位置可以使用剩余有效标记，并记录 fallback。关键关节无法恢复、骨段退化或异常短序列会跳过，逐段原因写入 conversion_report.json。不做平滑或骨长强制修正；帧率按下述方案重采样。

本次实际转换：1,980 个原始 Vicon 分片，1,936 个有效包，44 个跳过；深蹲 m01 的 200 段全部保留（train 120 / val 40 / test 40）。这些数字是本机输入的转换结果，并非数据集通用保证。

原始数据和已有转换不覆盖。输出目录若非空，转换器拒绝运行；再次转换请指定新的空目录。转换所需的关节表、动作表、划分及文件名解析已合入单文件，旧读取 / 体检和生成 / 打包脚本已移除。



## 帧率采样方案

`--fps 30` 表示输出为 30 FPS，所有已有参数仍需显式提供。先在原始 100 FPS 上修复缺失、映射关节、转换坐标，再在 3D 上按时间戳重采样，最后从重采样后的 3D 生成 2D，确保帧与 FPS 完全一致。

原始第 i 帧时间为 i/100；目标第 k 帧时间为 k/fps。令 u=k×100/fps，使用 floor(u) 与 ceil(u) 两帧的线性插值。30 FPS 时位置对应原始帧索引 0、3.333…、6.667…、10…，不会按固定间隔粗略抽帧或改变播放速度。100 FPS 保持原样；更高 FPS 可插值增加帧，但不增加真实观测信息。

输出帧数为 floor((N−1)×fps/100)+1，目标时间不超过原始末帧时间。不附加不在目标时间网格上的末帧，也不外推；因此末尾最多少于一个目标帧间隔（30 FPS 时 <33.33 ms），时长近似保留。输出 NPZ、meta.json 的 FPS / 帧数均更新，并记录原始 FPS、原始帧数和末尾时间差。`--max-gap` 仍以原始 100 FPS 帧计，与输出 FPS 无关。

这是线性插值方案，未附加抗混叠低通滤波；降采样会丢失高频信息，快速动作可能发生混叠。不会通过平滑或固定骨长来掩盖原始数据问题。
